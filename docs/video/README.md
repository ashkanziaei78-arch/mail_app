# ویدیو معرفی «میلینگ پرس» — پرونده ساخت

این پوشه توضیح می‌دهد ویدیو چطور ساخته شد و چطور دوباره ساخته می‌شود.
سناریو در `docs/video-scenario.md` است.

## خروجی‌ها

| فایل | مشخصات | کاربرد |
|---|---|---|
| `میلینگ-پرس.mp4` | ۱۹۲۰×۱۰۸۰ · ۳۰fps · ۳:۵۶ · H.264 + AAC | نسخه کامل، برای جلسه و ارائه |
| `میلینگ-پرس-کوتاه.mp4` | همان ابعاد · ۴۰ ثانیه | پیام‌رسان‌ها و شبکه‌های اجتماعی |
| `poster.jpg` | ۱۹۲۰×۱۰۸۰ | قاب پوستر / بندانگشتی |
| `contact-sheet.jpg` | ۱۲ قاب | مرور سریع ترکیب‌بندی‌ها |

فایل‌های ویدیویی به‌خاطر حجم در مخزن نگه داشته نشده‌اند؛ از همین دستورها دوباره ساخته می‌شوند.

## چطور ساخته شده

۱. **صحنه‌های پرده اول** (پنج مشکل) و **تخته قابلیت‌ها** تماماً با کد ساخته
   شده‌اند: HTML + CSS، بدون ویدیوی آماده و بدون تصویر با حق نشر. هر حالت تصویر
   تابعِ محضِ زمان است (`window.SEEK(t)`)، پس هر فریم تکرارپذیر است و رندر قطعی
   می‌ماند.

۲. **یازده بندِ پرده چهارم** ضبط واقعی از خودِ سامانه‌اند: سامانه به‌صورت محلی روی
   `localhost:3100` با همان پایگاه داده نمونه بالا می‌آید و Playwright از صفحه‌ها
   عکس می‌گیرد (`capture.mjs`). چیزی در ویدیو نشان داده نمی‌شود که در سامانه
   نباشد.

۳. **موسیقی** با کد ساخته شده (`score.py`): پیشروی آکوردی مینور در پرده اول،
   سکوت یک‌ثانیه‌ای، و باز شدن به ماژور از لحظه معرفی. هیچ قطعه دارای حق نشری
   استفاده نشده است.

۴. **رندر**: Playwright فریم‌به‌فریم عکس می‌گیرد و ffmpeg آن‌ها را به MP4 تبدیل
   می‌کند.

## بازسازی

```bash
# ۱) سامانه محلی را بالا بیاورید (برای ضبط صفحه‌ها)
npm run build:local && PORT=3100 npx next start

# ۲) در پوشه ساخت ویدیو
node capture.mjs          # عکس‌های رابط کاربری
python3 score.py          # موسیقی
node render.mjs           # ۷۰۸۰ فریم
ffmpeg -framerate 30 -i frames/f%05d.jpg -i score-final.wav \
  -c:v libx264 -crf 19 -pix_fmt yuv420p -c:a aac -b:a 192k -shortest میلینگ-پرس.mp4
```

## قاعده‌هایی که رعایت شد

- هیچ آمار، رضایت‌نامه یا مشتری ساختگی در ویدیو نیست. عددهای نمونه با برچسب
  **(نمونه)** مشخص شده‌اند.
- نام و ادعاها با خودِ محصول می‌خوانند: چهار کانال ابلاغ (پیامک، بله، تلگرام،
  ایتا) در صفحه «درگاه پیامک» سامانه واقعاً وجود دارند و در همان نما دیده می‌شوند.
- زیرنویس‌ها روی پرده تیره می‌نشینند تا کنتراست متن از ۴٫۵:۱ کمتر نشود.
- ویدیو بی‌صدا هم کامل خوانده می‌شود؛ موسیقی فقط بستر است.

## آنچه هنوز از شما لازم است

۱. نشان رسمی پارک (PNG شفاف) تا جای نشان موقت بنشیند.
۲. یک سربرگ رسمی واقعی برای ضبط صحنه‌های پرده سوم با داده واقعی‌تر.
۳. تصمیم درباره گوینده: نسخه فعلی بدون روایت است؛ اگر گوینده بخواهید متن روایت
   از همین زیرنویس‌ها در می‌آید.
۴. نشانی نهایی سامانه برای قاب پایانی (فعلاً نشانی Vercel گذاشته شده).
